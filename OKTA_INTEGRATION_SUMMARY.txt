================================================================================
  HOW IT WORKS
================================================================================

User Flow with Okta OIDC:

1. User visits: https://analysis.savantpraxis.com

2. ALB checks for authentication cookie
   - Not authenticated? Redirect to Okta

3. User logs in to Okta
   - Enters Okta username/password
   - MFA if configured

4. Okta validates and redirects back
   - Authorization code sent to ALB

5. ALB exchanges code for token (automatic)
   - ALB validates JWT token
   - Extracts user identity

6. ALB forwards request to Lambda with headers:
   - x-amzn-oidc-identity: user@company.com
   - x-amzn-oidc-data: JWT with user claims

7. Lambda extracts user identity
   - Converts email to SageMaker profile name
   - user@company.com → user-company-com

8. Lambda generates presigned URL
   - For the specific user's profile
   - 12-hour validity

9. User redirected to SageMaker Studio
   - Lands in THEIR personal workspace
   - Ready to work!

================================================================================
  METHOD 1: ALB WITH OKTA OIDC (RECOMMENDED)
================================================================================

✅ Recommended for most deployments
✅ Simplest setup
✅ No SAML configuration required
✅ 15-minute setup time

SETUP STEPS:

1. Create Okta OIDC Application
   ---------------------------------
   a. Log into Okta Admin Console
   b. Applications → Create App Integration
   c. Select: OIDC - OpenID Connect
   d. Select: Web Application
   
   Configuration:
   - App name: SageMaker Studio Portal
   - Grant type: ✓ Authorization Code
   - Sign-in redirect URI: https://analysis.savantpraxis.com/oauth2/idpresponse
   - Sign-out redirect URI: https://analysis.savantpraxis.com
   - Controlled access: Assign groups/users
   
   e. Save and note:
      - Client ID: 0oa1234567890abcdef
      - Client Secret: secret-value-here

2. Configure Terraform
   ---------------------------------
   Add to terraform.tfvars:
   
   # Enable custom domain (required)
   enable_custom_domain = true
   custom_domain_name   = "analysis.savantpraxis.com"
   route53_zone_id      = "Z05687192QVMDJJL9QM6A"
   
   # Enable Okta OIDC authentication
   enable_okta_auth             = true
   okta_issuer_url              = "https://dev-12345678.okta.com/oauth2/default"
   okta_client_id               = "0oa1234567890abcdef"
   okta_client_secret           = "secret-value-here"
   okta_authorization_endpoint  = "https://dev-12345678.okta.com/oauth2/default/v1/authorize"
   okta_token_endpoint          = "https://dev-12345678.okta.com/oauth2/default/v1/token"
   okta_user_info_endpoint      = "https://dev-12345678.okta.com/oauth2/default/v1/userinfo"
   okta_session_timeout         = 604800  # 7 days

3. Deploy Infrastructure
   ---------------------------------
   terraform init
   terraform apply
   
   Review changes and confirm.

4. Test Authentication
   ---------------------------------
   a. Open browser in incognito/private mode
   b. Navigate to: https://analysis.savantpraxis.com
   c. You'll be redirected to Okta login
   d. Enter your Okta credentials
   e. After authentication, you'll see the portal
   f. Click "Launch Studio"
   g. You're in SageMaker Studio with YOUR profile!

THAT'S IT! 15 minutes total.

================================================================================
  METHOD 2: IAM IDENTITY CENTER + OKTA SAML
================================================================================

✅ Best for enterprise multi-account setups
✅ Centralized AWS permission management
✅ 30-minute setup time

SETUP STEPS:

1. Enable IAM Identity Center
   ---------------------------------
   AWS Console → IAM Identity Center → Enable
   
   Get configuration:
   aws sso-admin list-instances
   
   Note:
   - Instance ARN: arn:aws:sso:::instance/ssoins-...
   - Identity Store ID: d-1234567890

2. Create Okta SAML Application
   ---------------------------------
   See OKTA_SETUP.md for detailed SAML configuration

3. Configure Terraform
   ---------------------------------
   Add to terraform.tfvars:
   
   enable_sso               = true
   sso_instance_arn         = "arn:aws:sso:::instance/ssoins-..."
   sso_identity_store_id    = "d-1234567890"

4. Configure Okta SAML in IAM Identity Center
   ---------------------------------
   IAM Identity Center → Settings → Identity source
   → Change to External identity provider
   → Upload Okta metadata

5. Deploy Infrastructure
   ---------------------------------
   terraform apply

6. Assign Permission Sets
   ---------------------------------
   IAM Identity Center → AWS accounts
   → Assign users/groups to permission sets created by Terraform

See OKTA_SETUP.md for complete SAML setup guide.

================================================================================
  USER IDENTITY MAPPING
================================================================================

How Lambda Maps Okta Users to SageMaker Profiles:

Okta Email                    →  SageMaker Profile Name
--------------------------------  ----------------------------------
jane.doe@company.com          →  jane-doe-company-com
john.smith@example.org        →  john-smith-example-org
admin@savantpraxis.com        →  admin-savantpraxis-com

Conversion Rules:
- Replace @ with hyphen (-)
- Replace . with hyphen (-)  
- Convert to lowercase
- Must be alphanumeric + hyphens only
- Maximum 63 characters

The Lambda handler does this automatically!

  SECURITY FEATURES
================================================================================

✅ All Traffic Over HTTPS
   - SSL/TLS certificate from ACM
   - Enforced by ALB

✅ Token Validation
   - ALB validates JWT tokens automatically
   - Invalid tokens rejected before reaching Lambda

✅ No Credential Storage
   - Lambda never handles passwords
   - Lambda receives only verified user identity
   - Client secrets stored in Terraform state (encrypted recommended)

   - ALB manages session cookies
   - Configurable timeout (default: 7 days)
   - Automatic refresh

✅ Least Privilege
   - Lambda only has SageMaker presigned URL permissions
   - ALB security group restricts traffic
   - IAM roles follow least privilege

✅ Audit Trail
   - CloudWatch logs capture all access
   - User identity logged in Lambda
   - ALB access logs available

================================================================================
  TROUBLESHOOTING
================================================================================

ISSUE: Redirected to Okta but "Access Denied"
----------------------------------------------
CAUSE: User not assigned to Okta application

SOLUTION:
1. Okta Admin Console
2. Applications → SageMaker Studio Portal
3. Assignments tab
4. Assign user or group

ISSUE: "User profile not found" error
--------------------------------------
CAUSE: SageMaker profile doesn't exist

SOLUTION (SSO Mode):
- Profile created automatically on first Studio access
- User must visit SageMaker Console first
- Or wait for next login attempt

SOLUTION (IAM Mode):
aws sagemaker create-user-profile \
  --domain-id <your-domain-id> \
  --user-profile-name "user-company-com" \
  --user-settings '{"ExecutionRole": "<execution-role-arn>"}'

ISSUE: Authentication loop (keeps redirecting)
-----------------------------------------------
CAUSE: Incorrect redirect URI in Okta

SOLUTION:
Verify redirect URI exactly matches:
https://analysis.savantpraxis.com/oauth2/idpresponse

ISSUE: Lambda can't extract user identity
------------------------------------------
CAUSE: ALB authentication not configured

SOLUTION:
1. Verify enable_okta_auth = true in terraform.tfvars
2. Run terraform apply
3. Check ALB listener rules:

aws elbv2 describe-listeners \
  --load-balancer-arn $(terraform output -raw alb_arn)

ISSUE: Session expires too quickly
-----------------------------------
CAUSE: Default session timeout

SOLUTION:
Set longer timeout in terraform.tfvars:
okta_session_timeout = 2592000  # 30 days
