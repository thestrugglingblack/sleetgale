YOUR QUESTIONS:
══════════════

1. Why "Invalid or Expired Auth Token" on SageMaker URL?
   → https://d-d4ujiazahn5b.studio.us-east-1.sagemaker.aws

2. Why "503 Service Temporarily Unavailable" on custom domain?
   → analysis.savantpraxis.com

╔═══════════════════════════════════════════════════════════════════════════════╗
║                              ANSWER #1                                        ║
╚═══════════════════════════════════════════════════════════════════════════════╝

"Invalid or Expired Auth Token" is NORMAL!

What's Happening:
─────────────────

✓ This is EXPECTED behavior for SageMaker Studio
✓ SageMaker URLs require authentication tokens that EXPIRE
✓ Tokens are valid for only 5-15 minutes
✓ You need to generate a FRESH URL each time you access Studio

This is NOT an error! This is how SageMaker security works.

╔═══════════════════════════════════════════════════════════════════════════════╗
║                              ANSWER #2                                        ║
╚═══════════════════════════════════════════════════════════════════════════════╝

"503 Service Unavailable" is EXPECTED (but indicates a problem)!

What's Happening:
─────────────────

✗ The Application Load Balancer has NO BACKEND TARGETS
✗ There's nothing for the ALB to forward traffic to
✗ SageMaker Studio CANNOT be accessed through an ALB + custom domain
✗ This architecture doesn't work for SageMaker Studio

The Real Problem:
─────────────────

Your infrastructure was set up expecting to proxy SageMaker Studio through
an ALB, but SageMaker Studio doesn't work that way!

╔═══════════════════════════════════════════════════════════════════════════════╗
║                        HOW TO ACCESS SAGEMAKER STUDIO                         ║
╚═══════════════════════════════════════════════════════════════════════════════╝

METHOD 1: AWS Console (EASIEST - RECOMMENDED)
══════════════════════════════════════════════

1. Go to: https://console.aws.amazon.com/sagemaker/
2. Click "Domains" in left sidebar
3. Click on domain: d-d4ujiazahn5b
4. Click on a user profile
5. Click "Launch" → "Studio"

AWS automatically generates a fresh presigned URL and opens Studio!

METHOD 2: AWS CLI (FOR AUTOMATION)
═══════════════════════════════════

aws sagemaker create-presigned-domain-url \
  --domain-id d-d4ujiazahn5b \
  --user-profile-name default-user \
  --region us-east-1 \
  --query 'AuthorizedUrl' \
  --output text

Copy the URL and paste into your browser.

METHOD 3: Python Script
═══════════════════════

import boto3

sagemaker = boto3.client('sagemaker', region_name='us-east-1')
response = sagemaker.create_presigned_domain_url(
    DomainId='d-d4ujiazahn5b',
    UserProfileName='default-user'
)
print(response['AuthorizedUrl'])

╔═══════════════════════════════════════════════════════════════════════════════╗
║                  WHY CAN'T I USE analysis.savantpraxis.com?                   ║
╚═══════════════════════════════════════════════════════════════════════════════╝

The Problem:
────────────

SageMaker Studio is NOT a traditional web application!

SageMaker Studio Requires:
  • Dynamic URLs that change per session
  • AWS authentication tokens in the URL
  • WebSocket connections
  • Session management by AWS

An ALB + Custom Domain CANNOT provide these!

What You Have Now:
──────────────────

analysis.savantpraxis.com
    ↓
  Route 53
    ↓
  ALB
    ↓
  Target Group
    ↓
  ??? NOTHING HERE ← This is why you get 503

Why 503:
────────

✗ No targets registered in ALB target group
✗ SageMaker Studio can't be a target
✗ ALB has nowhere to send traffic

╔═══════════════════════════════════════════════════════════════════════════════╗
║                            WHAT WENT WRONG?                                   ║
╚═══════════════════════════════════════════════════════════════════════════════╝

Root Cause:
───────────

The infrastructure was designed with a misunderstanding of how SageMaker works.

Misconception:
  "I can access SageMaker Studio through a custom domain like any web app"

Reality:
  SageMaker Studio requires presigned URLs generated by AWS - you cannot
  proxy it through an ALB with a static custom domain.
